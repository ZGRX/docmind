# 后续升级路线

当前版本适合单人本地演示。建议按瓶颈出现的顺序升级，每一步都保留可观察的指标和回归样本。

| 阶段 | 方向 | 具体改动与学习点 |
| --- | --- | --- |
| 1 | Docker 部署 | 配置真实域名、HTTPS、环境变量、持久卷与备份；不要公开没有鉴权的当前版本。 |
| 2 | PostgreSQL | 替换 SQLite，增加 Alembic 迁移，验证并发写入与索引。 |
| 3 | 对象存储 | 原文件转存 S3 兼容存储，数据库只保存对象键。 |
| 4 | Celery + Redis | 上传请求只创建任务，后台解析与向量化；Redis 作消息 broker，也可存临时进度。 |
| 5 | 多用户鉴权 | 登录、owner_id、文档与会话权限、向量检索过滤；补充安全测试。 |
| 6 | BM25 与 hybrid search | 增加关键词检索，与向量检索融合，改善专有名词和精确匹配。 |
| 7 | reranker | 先多召回，再重排候选，减少送入 LLM 的无关 chunk。 |
| 8 | 性能测试 | 测上传吞吐、索引耗时、检索延迟、首字延迟、并发会话。 |
| 9 | 监控 | 结构化日志、错误率、任务队列长度、模型耗时和成本指标。 |
| 10 | 云部署 | 使用托管数据库/对象存储、CI/CD、密钥管理、告警与数据备份演练。 |

先建立小型评测集：为几份文档人工写问题、标准答案及对应 chunk。每次调整 chunk size、top-k、Embedding、BM25 或 reranker 时，比较检索命中率、答案质量、引用准确率、延迟和调用费用。
